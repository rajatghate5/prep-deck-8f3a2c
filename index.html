Three rules for the room

  • Don't start with React. Start every answer from RxMen, Evify or ERoomRent — the backend work.
  • Don't say "microservices from day one." Say one codebase, kept tidy, split later when something forces it.
  • Don't defend a number you didn't measure. Say how you'd measure it now instead. Being vague is fine. Making something up is not.

Two-evening plan

How you measured it — say the tool

  • Frontend (~30%): Lighthouse + DevTools Performance for LCP/TTFB · React DevTools Profiler for re-renders · PostHog for real-user vitals.
  • API (~20%): Postman Collection Runner for endpoint timing · EXPLAIN (ANALYZE, BUFFERS) + pg_stat_statements for queries · CloudWatch p95/p99 in prod.
  • Volume (10k+): CloudWatch / API Gateway request count — a counter, not an estimate.
  • Mongo: .explain("executionStats") · the profiler for slow ops · Atlas Performance Advisor.
  • Correctness: Jest + Supertest on NestJS services and routes · Postman collections with pm.test assertions as API contract/smoke tests (Newman to run them in CI) · Playwright for critical UI flows, pre-merge.
  • Never claimed: a formal load test. If asked, say k6/autocannon is what you'd use and that it's a real gap.
